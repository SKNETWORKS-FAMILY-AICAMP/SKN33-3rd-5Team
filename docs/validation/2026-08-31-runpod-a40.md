# RunPod A40 학습·추천·QA 및 최신 main 통합 검증

검증일: 2026-08-31. 실행 성공, 응답 형식 검사, 실제 답변의 사실 정확도를 구분한다.
아래 진행률은 시험 정답률이 아니라 README의 실행 가능한 Streamlit MVP 목표에 대한 추정이다.

이 문서는 당시 A40 실행 이력을 보존한다. 이후 최신 main 위의 `feat/fine-tuning`에
서비스·화면·인용 검증 수정을 직접 반영했다. 현재 반영 상태와 새 검사 결과는
[기존 코드 통합 검증](2026-08-31-finetuning-integration.md)을 참고한다.

## 판정

- 받은 세 파일로 A40에서 3 epoch QLoRA 학습과 adapter 저장·실제 추론을 완료했다.
- 조건 추출 품질은 Base보다 개선됐지만 holdout 전체 JSON 완전일치는 45%다.
- 이전 브랜치에서 QA 7건의 기대 상태와 추천 4건의 응답 생성은 통과했다. 그러나 추천
  문장에 모델 사양 혼동과 근거 없는 추론이 발견돼 제품추천 품질 완료로 판정하지 않는다.
- 최신 main에는 파인튜닝 변경과 무관한 기존 테스트 실패 5건과 추천 폼 진입점 누락이
  있다. 별도 검증 사본에서 수정안을 작성·테스트했으며 원본 브랜치에는 강제 병합하지 않았다.
- 최신 main 통합 수정안에서도 QA 7/7 기대 상태 처리를 확인했다. 그러나 부팅 답변이
  인용 원문에 없는 블루투스 오류 진단까지 주장해 **QA 의미 정확도도 미완료**다.
- 최신 통합본의 추천도 4/4 응답 생성에 성공했으나, 다른 제품의 표를 인용하거나
  근거 부재를 부정적 사실로 단정하는 문제가 남았다.
- 수정 검증본의 Streamlit AppTest에서도 실제 GPU 서비스로 QA·추천 폼을 각각 제출해
  두 경로 모두 `answered`, 화면 error/exception 0건을 확인했다. 공개 웹 배포나
  모든 브라우저·사용자 시나리오 검증을 완료했다는 의미는 아니다.

발견한 추천 품질 결함:

1. Pi 500의 설명에 같은 검색 청크에 있던 Pi 500+의 내장 SSD를 섞었다.
2. 전원 공급 전류·소비 전류를 원격 관리 성능의 우수성으로 연결했다.
3. 여러 제품의 행과 RAM·Wi-Fi 수치를 혼동했다. 인용 ID가 존재해도 주장을 지지하는지

LLM 출력의 인용 공백·쉼표 표기 정규화, 인용 뒤 마침표 허용, 제한된 재시도,
혼합된 보류 표식의 안전 처리와 짧은 출력 지시를 추가했다. 이 수정은 형식과 안전 보류를
개선하지만 의미적 사실 검증을 대신하지 않는다. 추천 사실 오류를 해결했다고 주장하지 않는다.

## 최신 main 검증과 수정안

최신 fetch 기준 main: `66044965a6d7ad8d6d5ba50f52bb4b95edb5b797`.
HEAD 대비 39개 파일이 달라졌고, 현재 변경과 겹치는 파일은 4개다. 개행을 정규화한
3-way 병합에서 텍스트 충돌은 0건이었다. 논리적 연결 오류는 별도로 존재한다.

원본 작업을 stash/reset/checkout하지 않고 `artifacts/main-integration-6604496/` 아래에
main, 단순 통합본(combined), 수정 검증본(corrected)을 각각 만들었다.

| 검증 대상 | 로컬 전체 테스트 |
|---|---|
| 최신 main 그대로 | 157 passed / 5 failed / 1 skipped |
| main + 현재 파인튜닝·LLM 변경 | 184 passed / 동일한 5 failed / 1 skipped |
| 연결 수정안 + 추가 통합 회귀 검사 | **192 passed / 1 skipped** |

수정 검증본을 새 A40에서도 그대로 실행해 **193 passed**를 확인했다. Windows에서
생략된 symlink 검사도 Linux에서 통과했다. 테스트 통과가 모든 실제 답변의 사실 정확도를
보증하는 것은 아니다.

같은 실패 5건의 원인:

- `test_rag.py`: 저장소에 없는 legacy manifest를 직접 참조하는 테스트 1건.
- `rag_qa_service.py`: 재시도 helper 호출이 누락되고 `validated_generation`을 참조해
  trace 경로와 재시도 테스트 3건 실패.
- `recommendation_rag_service.py`: 같은 변수 연결 누락으로 추천 trace 테스트 1건 실패.
- 추가로 Streamlit이 호출하는 `answer_form`이 서비스에 없었다. 기존 전체 테스트에는
  이 UI→서비스 경로가 포함되지 않았다.

수정 검증본은 helper를 실제 호출하고, 보류를 에러로 바꾸지 않으며, 한국어 검사를
유지한다. 내부 재시도 횟수도 trace에 반영한다. 폼 진입점은 기존 `recommend_form`을
재사용해 명시적 UI 조건을 보존하고, 조건 추출 전에 같은 안전 검사를 적용한다.
Legacy schema 거부 검사는 임시 manifest를 직접 생성해 외부 파일 의존성을 제거했다.

검토용 수정안: [integration-fixes.patch](../../artifacts/main-integration-6604496/integration-fixes.patch).
이는 **단순 통합본 대비 추가 수정안**이다. main 전체나 기존 변경을 포함하는 패치가 아니므로
기존 브랜치에 무조건 적용하지 않는다. 원본 팀 RAG·문서 파이프라인·catalog·UI 파일은
수정하지 않았고 Git commit/push나 Hugging Face 업로드도 하지 않았다.

## RunPod 마이그레이션 확인

- 재접속한 GPU도 A40이며 CUDA 사용 가능, 모델 SHA256은 이전과 동일했다.
- 최종 adapter SHA256:
  `23f9308d310143a60869077e1a947455bf419676e8283d0c86dcd3b24bdecd4f`.
- 이전 `artifacts/runpod-validation` 문서·색인 자료는 새 Pod에서 없었다.
- `.venv` 일부 distribution 파일/metadata가 누락돼 실제 import와 `pip check`가 실패했다.
  손상된 distribution을 기록된 같은 버전으로 복구한 뒤 `pip check`를 다시 통과했다.
- 이미 학습한 adapter를 재사용하며 재학습은 하지 않았다.
- 통합 검증은 `/workspace/main-integration-6604496`에서 수행한다. 기존 프로젝트와 모델
  경로를 덮어쓰지 않는다. 검증 사본은 복구한 기존 Python 환경을 사용한다.

검증 corpus는 팀의 source_registry_v3와 고정 공식 문서 commit
`75331a79fbf32d2403b7547729ddccf553873b09`로 재생성한다. 팀의 최종 승인 corpus/색인과
동일하다고 가정하지 않으며, 최신 main의 Manifest 1.1 검사도 함께 확인한다.

재생성 결과는 **18개 문서·270개 청크**다. `run_pipeline.py` 직접 실행은 최신
`src.contracts` import 때문에 실패했으며 `python -m document_pipeline.ingestion.run_pipeline`
방식으로 완료했다. 원본 팀 파이프라인 코드는 고치지 않았다.
동일 manifest로 Chroma의 `rpi_official` collection 270개 청크 색인도 완료했다.

최신 통합본의 실제 QA도 7/7 기대 상태와 인용 형식 검사를 통과했다. 다만 부팅 답변의
세 번째 항목에 “블루투스, SPI, I2C 등에서 오류가 발생했을 경우 LED 플래시 패턴을 통해
이를 식별”한다는 주장이 있다. 사용한 C1 LED 코드 표에는 SPI EEPROM·I2C 등의 항목은
있지만 블루투스 항목은 없다. 이는 **인용이 붙어 있어도 해당 사실을 근거가 지지하지
않는 구체적 반례**다. SSH와 OS 설치 답변은 이번 표본의 핵심 절차를 인용 원문과 대조했지만,
전체 QA 정확도나 Citation Precision을 산출할 만큼 검수한 것은 아니다.

증거: [최신 GPU QA 원문과 인용](../../artifacts/main-integration-6604496/gpu-results/gpu-qa-results.json).

## 진행률과 남은 완료 조건

실제 GPU 서비스와 연결된 Streamlit AppTest 결과는 초기 화면·QA 제출·추천 폼 제출
모두 error/exception 0건이었다. 두 제출 결과는 `answered`였다. 브라우저 레이아웃,
공개 URL, 다중 사용자 성능은 이번 검사에 포함되지 않는다.

검증 사본에서 다시 실행하려면 다음처럼 실행한다. 이 경로는 원본 프로젝트와 다르다.

```bash
cd /workspace/main-integration-6604496
export PYTHONPATH=/tmp/picare-runtime-libs
.venv/bin/python -m src.services.rag_qa_cli --query "SSH를 활성화하려면?" --json --trace
.venv/bin/python -m src.services.recommendation_rag_cli --query "홈 서버 보드를 추천해 주세요." --json --trace
```

임시 라이브러리 경로가 없어진 경우 동일한 버전으로 다시 준비한다.

```bash
.venv/bin/python -m pip install --no-deps --target /tmp/picare-runtime-libs transformers==4.57.6
```

최종 확인 시 검증 프로세스는 종료됐고 A40 사용 메모리와 GPU 사용률은 0이었다.
Pod 자체를 중지하거나 삭제하지는 않았다.
