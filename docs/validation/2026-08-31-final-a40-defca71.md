# 최신 fix/dev의 새 RunPod A40 최종 재실행

검증일: 2026-08-31. **실제 GPU 실행·서비스 연결 검증은 완료했고, 답변의 의미 정확도는 미완료다.**
학습된 LoRA를 복원해 실행했으며 재학습·프롬프트 조정·holdout 재평가는 하지 않았다.

## 검증한 코드와 환경

- 기준: `fix/dev`, `defca713dcc9e480c0ab7b9eb4e19443b1e6d858`.
- 추가 수정 2개: `tests/test_rag.py`가 생성한 임시 legacy manifest를 실제로 읽도록 복구했고,
  `src/services/recommendation_rag_cli.py`의 출처 중첩 반복문을 제거했다.
- 위 수정까지 포함한 소스·입력 150개 파일의 해시가 전송 후와 GPU 검사 종료 후 동일했다.
  순수 HEAD만 실행한 결과로 해석하지 않는다. 소스 해시는 커밋 전 작업 사본 기준이다.

  해당 패키지를 설치했고 검증 실행에서는 표준 다운로드를 사용했다. 최초 실패 로그도 보존했다.

QA 생성기와 조건 추출기는 모두 실제 CUDA 4-bit로 실행했다. 두 모델의 실제 revision은
학습 당시의 `cdbee75f17c01a7cc42f958dc650907174af0554`와 일치했다.
LoRA 가중치 SHA-256도 기존 백업과 동일하다.

```text
23f9308d310143a60869077e1a947455bf419676e8283d0c86dcd3b24bdecd4f
```

공식 원문 commit `75331a79fbf32d2403b7547729ddccf553873b09`의 검증된 백업을 최신
`source_registry_v3.csv`와 파서로 다시 처리했다. **18개 문서·270개 청크**, 미디어
**71개(이미지 70·영상 1)**를 생성했고 49개 청크에 미디어가 연결됐다. 카탈로그 정합성도
통과했다. 이전 Chroma DB는 재사용하지 않고 `data/indexed/chroma_final_defca71`에
270개 청크를 새로 색인했다. E5 revision은 `d128750597153bb5987e10b1c3493a34e5a4502a`다.
이는 현재 코드로 재생성한 검증 corpus이며 팀의 별도 운영 색인과 동일하다고 가정하지 않는다.

이는 종단 p50/p95, 동시 사용자 성능, 전체 GPU 메모리 사용량 측정이 아니다.
AppTest는 실제 서비스를 사용했지만 브라우저 레이아웃·원격 미디어 재생·공개 배포 검증은 아니다.

## Dev 조건 추출 오류 분석

동일한 기존 LoRA로 dev 40건만 평가했다. 입력 파일은 학습 당시 SHA-256과 동일하며
train 300 / dev 40 / holdout 20의 원문·분할을 수정하지 않았다.

| 지표 | 결과 |
|---|---:|
| JSON Schema 준수 | **39/40 (97.5%)** |
| 전체 조건 Exact Match | **23/40 (57.5%)** |
| 필드별 Macro F1 평균 | **67.60%** |
| 정답이 null인 필드에 값을 생성한 비율 | **0.68%** |
| 제품 추천 Top-1 정확도 | 산출 불가 — 평가 정답 제품 ID 없음 |

스키마 실패 1건은 JSON 문법 문제가 아니라 `use_case`에 허용되지 않은 `sensor_monitoring`
값을 넣은 경우다. 이는 `task` 값과의 혼동이며 서버가 그대로 거절했다. 검사를 통과시키려고
해당 값을 자동 치환하지 않았다.

유효한 예측 39건 중 필드 불일치는 task 7건, use_case 5건, intent 4건,
clarification_questions 4건 등이었다. 한 레코드에 여러 오류가 있을 수 있다.
스키마 실패를 포함하면 전체 불일치 레코드는 17건이다. 유효 예측에서 필요한 필드 값 누락은 11개,
불필요한 값 추가는 2개였다. 샘플과 필드별 상세 내역은 Git 제외 결과에 보관했다.

현재 평가기의 Macro F1은 예측의 invalid 클래스를 포함하므로 한 스키마 실패도 각 필드의
평균에 영향을 준다. 측정 중 평가 방식을 바꾸지 않았다. **이번 dev 점수는 이전 holdout의
45% Exact Match·90.61% Macro F1과 직접 비교할 수 없다.** 이 결과만으로 추가 학습의
필요성이나 개선·하락을 단정하지 않는다. 다음 보완은 dev의 intent/use_case/task 구분부터
검수하고, 변경이 끝난 뒤 고정된 별도 평가 절차로 확인해야 한다.

## 남은 사실·근거 문제

인용 ID와 형식이 유효한 것과 원문이 주장을 지지하는 것은 다르다. 아래는 수동 대조로
확인한 반례이며 정식 의미 정확도 점수나 전체 문장 검수 결과는 아니다.

1. **부팅 QA:** SD 카드 활동 시 LED가 빨강에서 초록으로 바뀐다고 설명했다. 인용 C2는
   SD 카드 활동을 LED가 잠깐 꺼지는 깜빡임으로 설명한다. 전원/부팅 색 변화와 혼동했다.
2. **카메라 추천:** Zero 2 W의 Wi-Fi 범위가 제한되어 장거리 관찰에 부적절할 수 있다고
   판단했다. C2/C3는 연결 규격과 대역을 제시하지만 통신 거리나 관찰 실측 근거를 제공하지 않는다.
3. **교육 추천:** 본문은 Pi 5의 구체적 근거가 없어 추천할 수 없다고 했지만 Pi 5 카드가
   표시됐다. 카드에는 Pi 400 표 C1, Pi 4 표 C2, 범용 OS 설정 C4가 연결됐다.
   후보·카드 인용이 document_id로 연결되는 경로를 보완해야 한다. C4에는 Pi 5 태그가 있어
   단순 제품 태그 검사만으로도 충분하지 않으며, 조건별 사양을 지지하는 청크·표 행이 필요하다.

따라서 **GPU 재실행과 서비스 연결 작업은 완료**, 조건 추출 품질 및 RAG·추천 사실 검수는
후속 작업으로 남는다. 이번에는 smoke 질문에 맞춘 프롬프트 수정이나 RAG 추천 정책 변경을
하지 않았다. 학습용 LoRA는 조건 추출기이고 QA·추천 설명 생성은 별도 Base 모델이므로,
설명 오류가 모두 LoRA 재학습으로 해결되는 것은 아니다.

새 Pod에서는 의존성을 다시 설치해야 하며 `.venv` 링크만 복사해서는 복구되지 않는다.
로컬 Python/PyCharm과 원격 모델 버전을 혼동하지 않도록 현재 `.env`와 아래 비밀 없는
설정 백업을 참고한다.
